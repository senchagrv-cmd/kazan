# 1. HEADER + HERO — ATTENTION

### Цель

За 3–5 секунд объяснить:
**что продаём → для кого → главное отличие → что делать дальше.**

### Layout & UI

Desktop:

```text
┌─────────────────────────────────────────────────────────────┐
│ LOGO        Проекты  Как работаем  Стоимость  FAQ    CTA   │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  РЕМОНТ КВАРТИР В КАЗАНИ             ┌───────────────────┐  │
│                                      │ МОЙ ОБЪЕКТ        │  │
│  Ремонт без сюрпризов                │                   │  │
│  по цене и срокам                    │ 64 м²             │  │
│                                      │ ███████████░ 74%  │  │
│  От 12 900 ₽/м² · от 45 дней         │                   │  │
│  · гарантия 3 года                   │ Сейчас            │  │
│                                      │ Чистовая отделка  │  │
│  Фиксируем стоимость...              │                   │  │
│                                      │ Бюджет 1 160 000₽ │  │
│  [Рассчитать бюджет]                 │ Отчёт: сегодня    │  │
│  [Смотреть проекты]                  └───────────────────┘  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Текст

**H1:**
**Ремонт без сюрпризов по цене и срокам**

Под ним:

**От 12 900 ₽/м² · от 45 дней · гарантия 3 года**

**Фиксируем стоимость и сроки до начала работ, показываем прогресс ремонта и согласовываем дополнительные расходы до их выполнения.**

**Вам не нужно становиться прорабом собственной квартиры.**

CTA:

**Рассчитать бюджет за 2 минуты**

Secondary:

**Смотреть реальные проекты →**

Микротекст:

**Бесплатный замер · подробная смета · без обязательств**

### UX-фишки

Dashboard должен быть **главным визуальным объектом**, а не декоративной карточкой.

Анимация при загрузке:

`0% → 74%`

`Стяжка ✓ → Плитка ● → Двери ○`

Очень лёгкая, без тяжёлого JS.

На мобильном:

* сначала текст;
* затем dashboard;
* CTA на всю ширину;
* dashboard превращается в горизонтальную компактную карточку;
* часть второстепенных данных скрывается.

После прохождения:

```text
ОРИЕНТИРОВИЧНЫЙ БЮДЖЕТ
```

### Цель

Преобразовать главное обещание «прозрачность» в конкретный механизм.

### Layout & UI

Центральный горизонтальный flow:

```text
ПРОБЛЕМА
   ↓
ФИКСИРУЕМ
   ↓
ОБЪЯСНЯЕМ
   ↓
ПРЕДЛАГАЕМ
   ↓
СОГЛАСОВЫВАЕМ
   ↓
ВЫПОЛНЯЕМ
```

Можно оформить как UI-поток с маленькими фото объекта.

### Заголовок

# Что будет, если мы найдём проблему?

Основной пример:

**Обнаружили старую проводку после демонтажа.**

**01** Фиксируем проблему на фото
**02** Объясняем, почему её нельзя оставить
**03** Показываем варианты решения
**04** Рассчитываем стоимость
**05** Получаем ваше согласование
**06** Выполняем

Финальная фраза:

**Сначала показать. Потом посчитать. Потом согласовать. Потом сделать.**

### UX

На scroll path поэтапно подсвечивается.

В mobile flow становится вертикальным.

Это одна из ключевых секций сайта — её стоит визуально выделить сильнее остальных.

### Цель

Доказать всё, что мы обещали выше.

### Layout & UI

### Текст

### Кейс №01

**Квартира 64 м² · ЖК «Символ»**

82 дня · 1 160 000 ₽ · новостройка

**Задача**
Семья хотела подготовить квартиру к переезду без ежедневного контроля стройки.

**Проблема**
Владельцы не могли постоянно приезжать на объект и хотели понимать, что происходит с ремонтом и бюджетом.

Персональный прораб, еженедельные фотоотчёты, поэтапная работа и согласование дополнительных расходов до выполнения.

**Результат**

# 14. FAQ + CHECKLIST LEAD MAGNET — ACTION

### Цель

### Layout & UI

FAQ accordion.

Правая:

большая карточка lead magnet.

```text

│ 17 ВОПРОСОВ                │
│ подрядчику перед ремонтом  │

│                           │

```

### FAQ

**Может ли смета измениться?**

Да, если меняется объём работ или появляются дополнительные задачи. Дополнительные работы начинаем только после согласования стоимости.

**Что будет, если найдётся скрытая проблема?**

Фиксируем её, объясняем причину, показываем варианты и согласовываем стоимость до выполнения.

**Кто покупает материалы?**

Можно купить самостоятельно или поручить закупку нам.

**Что будет при задержке?**

Срок закрепляется в договоре. При задержке по нашей вине предусмотрена компенсация.

**Как я контролирую ремонт?**

Персональный прораб + еженедельные фотоотчёты.

**Что если мне не понравится результат?**

Проходим финальную приёмку по чек-листу из 37 пунктов и устраняем замечания согласно условиям договора.

### Lead magnet

# Не выбирайте подрядчика на доверии

**Скачайте чек-лист из 17 вопросов, которые стоит задать перед подписанием договора.**

**Получить чек-лист →**

### UX

FAQ — native `<details>` или accordion component.

На mobile lead magnet должен идти **после FAQ**, а не занимать половину первого экрана.

Не нужно делать 20 разных анимаций.

Fade + translateY при появлении секции.

### 2. Dashboard progress

Прогресс ремонта заполняется один раз.

### 3. Timeline

Этапы подсвечиваются последовательно.

### 4. Problem protocol

Шаги flow появляются по мере scroll.

Очень лёгкий drag/tap interaction.

Все анимации должны уважать:

`prefers-reduced-motion`.

# ЧЕГО НЕ ДЕЛАТЬ

### Не делать

* огромные декоративные видео на Hero;
* autoplay background video;
* Lottie-файлы на каждый блок;
* тяжёлые 3D-модели;
* 15 разных hover-анимаций;
* бесконечный marquee;
* огромные фотографии без оптимизации;
* длинные полотна текста;
* одинаковые карточки в каждой секции;
* повторять «12 900 / 45 дней / 3 года» пять раз.

### Почему

Мы продаём **контроль и понятность**.

Если сам сайт перегружен, хаотичен и медленный, он визуально опровергает собственное обещание.
