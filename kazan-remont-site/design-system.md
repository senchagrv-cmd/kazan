# .cursorrules

# Дизайн-система и визуальное направление

# Проект: Лендинг ремонта квартир в Казани

# Визуальные референсы: Stripe + Linear

# ВАЖНО: не копировать бренды. Использовать принципы, а не фирменный стиль.

---

## 0. ОСНОВНАЯ КОНЦЕПЦИЯ ДИЗАЙНА

Сайт должен восприниматься как:

**«Ремонт как управляемый, прозрачный и хорошо организованный продукт».**

НЕ:

* типичный сайт строительной компании;
* дешёвая услуга ремонта;
* шаблонный лендинг;
* элитная студия дизайна интерьера;
* буквальная копия SaaS-дашборда.

Визуальный язык объединяет три направления:

### 1. Stripe

Использовать:

* крупную уверенную типографику;
* большое количество воздуха;
* сильную визуальную иерархию;
* модульную структуру секций;
* CTA, ориентированные на конверсию;
* числовые доказательства;
* аккуратную подачу продукта;
* чистую композицию.

### 2. Linear

Использовать:

* тёмные интерфейсные поверхности;
* тонкие границы;
* минимальные тени;
* точные отступы;
* компактные UI-карточки;
* dashboard-эстетику;
* статусы и индикаторы;
* аккуратные hover/press states;
* визуальную системность.

### 3. Наш бренд

Добавить:

* реальные фотографии квартир;
* реальные строительные процессы;
* сметы;
* сроки;
* этапы ремонта;
* контроль объекта;
* материалы;
* приёмку;
* визуализацию процесса ремонта.

Главная задача:

**не сделать сайт похожим на Stripe или Linear, а создать собственный язык на основе их принципов.**

---

# 1. ОБЩИЙ ВИЗУАЛЬНЫЙ ХАРАКТЕР

Сайт должен ощущаться:

* премиальным;
* спокойным;
* умным;
* точным;
* современным;
* технологичным;
* надёжным;
* минималистичным;
* структурированным;
* дорогим, но не люксовым;
* уверенным, но не агрессивным.

Посетитель должен подумать:

> «У этой компании есть система».

А не:

> «У этой компании просто красивый сайт».

---

# 2. ЦВЕТОВАЯ СИСТЕМА

Основной фон:

```css
--background: #F7F7F5;
```

Использовать очень светлый тёплый нейтральный фон как основную поверхность страницы.

Не использовать чистый белый для каждого блока.

---

Основной тёмный:

```css
--foreground: #101114;
```

Использовать почти чёрный вместо абсолютного #000000.

---

Дополнительная тёмная поверхность:

```css
--surface-dark: #17181C;
```

Тёмные секции должны ощущаться как sophisticated product interface.

---

Вторичный текст:

```css
--text-secondary: #6F727A;
```

Использовать для второстепенной информации.

---

Граница:

```css
--border: rgba(16,17,20,0.10);
```

Тёмная граница:

```css
--border-dark: rgba(255,255,255,0.12);
```

---

Основной акцент:

```css
--accent: #635BFF;
```

Использовать сдержанный электрический индиго-цвет.

ВАЖНО:

Не заливать страницу фиолетовым.

Акцент использовать преимущественно для:

* главных CTA;
* активных состояний;
* прогресс-баров;
* важных цифр;
* выбранных состояний калькулятора;
* небольших визуальных акцентов.

---

Дополнительный тёплый цвет материалов:

```css
--material-accent: #D6C5A8;
```

Использовать очень умеренно — только там, где речь идёт о материалах, интерьере или тёплых визуальных акцентах.

Не добавлять случайные цвета.

Палитра должна оставаться сдержанной.

---

# 3. ТИПОГРАФИКА

Типографика — один из главных элементов визуального стиля.

Предпочтительный стек:

```css
font-family:
Inter,
Geist Sans,
system-ui,
-apple-system,
BlinkMacSystemFont,
"Segoe UI",
sans-serif;
```

Использовать одно основное семейство шрифтов по всему сайту.

НЕ смешивать большое количество декоративных шрифтов.

---

## H1 Desktop

Размер:

64–80px

Начертание:

600–700

Высота строки:

0.95–1.05

Letter-spacing:

примерно -0.04em до -0.06em

---

## H2 Desktop

Размер:

48–64px

Начертание:

600–700

Высота строки:

1.0–1.05

---

## Большой текст

18–20px

Line-height:

1.45–1.6

---

## Основной текст

16px

Line-height:

1.5

---

## Маленький UI-текст

12–14px

Line-height:

1.35–1.45

---

## Цифры и метрики

Использовать очень крупную типографику.

Числа должны ощущаться как продуктовые метрики, а не как рекламные бейджи.

Избегать:

* огромных абзацев CAPS LOCK;
* декоративных шрифтов;
* чрезмерного выделения жирным;
* слишком большого line-height;
* длинных текстовых блоков.

---

# 4. ТИПОГРАФИЧЕСКАЯ ИЕРАРХИЯ

Каждая секция должна мгновенно читаться визуально.

Приоритет:

1. Eyebrow / метка секции
2. Большой заголовок
3. Короткое описание
4. Контент / карточки
5. CTA

Пример:

```text
01 / КОНТРОЛЬ

Что будет,
если мы найдём проблему?

Если на объекте обнаружилась проблема...
```

Эта иерархия должна системно повторяться.

---

# 5. GRID / СЕТКА

Desktop:

```text
max-width: 1280–1360px
```

Использовать:

```text
12-column grid
```

Основной контейнер:

```css
width: min(100% - 48px, 1360px);
```

Desktop-боковые отступы:

24–48px.

Большие секции должны выравниваться по одной общей сетке.

НЕ центрировать случайные элементы независимо друг от друга.

Весь сайт должен ощущаться как единая система.

---

# 6. MOBILE GRID

Мобильный контейнер:

```text
padding-left: 16–20px
padding-right: 16–20px
```

Не допускать горизонтального overflow.

Desktop 12-column grid на мобильном преимущественно превращается в:

```text
1 column
```

Карточки обычно складываются вертикально.

НЕ просто уменьшать desktop-макет.

Mobile должен быть самостоятельной композицией.

---

Ориентиры:

Mobile:

72–112px.

Не создавать случайные значения отступов без необходимости.

---

# 8. СТРУКТУРА СЕКЦИЙ

Каждая секция должна ощущаться частью одной продуктовой системы.

Предпочтительная структура:

```text
метка
↓
заголовок
↓
короткое описание
↓
контент
```

Не использовать:

* декоративные разделители без функции;
* случайные цвета фона;
* огромное количество карточек;
* одинаковый контейнер вокруг каждого текста.

Не каждая секция должна быть карточкой.

Воздух — часть дизайна.

---

# 9. КАРТОЧКИ

Карточки должны восприниматься как UI-модули.

Border:

```text
1px solid var(--border)
```

Radius:

```text
14–18px
```

Фон:

слегка отличающийся от основного фона страницы.

Тени:

минимальные.

Приоритет:

**border > shadow**

Не использовать:

* большие размытые тени;
* glassmorphism;
* чрезмерные градиенты;
* радиусы 30px+;
* neumorphism.

Карточки должны ощущаться точными и спроектированными.

---

# 10. DASHBOARD UI

Dashboard — главный визуальный элемент сайта.

Он должен быть вдохновлён интерфейсной эстетикой Linear.

Состав dashboard:

* статус проекта;
* прогресс;
* бюджет;
* завершённые этапы;
* текущий этап;
* следующий этап;
* последний отчёт;
* статусы задач.

Пример:

```text
МОЙ ОБЪЕКТ
Квартира · 64 м²

74%

Чистовая отделка

Бюджет
1 160 000 ₽

Освоено
842 000 ₽

Последний отчёт
Сегодня · 18:42
```

Использовать:

* тонкие разделители;
* компактные подписи;
* маленькие status dots;
* небольшую типографику;
* метаданные;
* сдержанный акцентный цвет.

Dashboard должен визуализировать контроль.

Это НЕ должен быть фальшивый SaaS-интерфейс.

Он должен представлять реальный процесс ремонта.

---

# 11. HERO

Hero — самая важная визуальная секция.

Desktop:

```text
grid-cols-12
```

Левая часть:

5–6 колонок

Правая часть:

6–7 колонок

Слева:

* eyebrow;
* H1;
* описание;
* CTA;
* доверительные сигналы.

Справа:

большой dashboard ремонта.

Не использовать обычную stock-фотографию квартиры на весь Hero.

Dashboard должен быть главным визуальным объектом.

Hero должен ощущаться скорее как запуск современного продукта, чем как обычный сайт подрядчика.

---

# 12. ФОН HERO

Hero должен оставаться минималистичным.

Допустимо:

* очень лёгкая текстура;
* едва заметная сетка;
* очень мягкий градиент.

НЕ использовать:

* огромные цветные gradient blobs;
* неоновое свечение;
* animated mesh gradients;
* частицы.

В центре внимания:

**H1 + CTA + Dashboard.**

---

# 13. КНОПКИ

Кнопки должны ощущаться как качественный product UI.

Основная кнопка:

Background:

```text
var(--foreground)
```

или

```text
var(--accent)
```

Text:

white

Border-radius:

10–12px

Height:

44–52px

Horizontal padding:

18–24px

Font:

14–16px

Weight:

600

Основной CTA должен иметь сильный контраст.

---

Вторичная кнопка:

* transparent;
* subtle border;

или

* текстовая кнопка.

Избегать:

* огромных pill-кнопок;
* градиентных кнопок;
* глянцевых эффектов;
* чрезмерных теней.

---

# 14. СОСТОЯНИЯ КНОПОК

Hover:

```text
translateY(-1px)
```

Допустимо слегка изменить фон.

Добавлять очень лёгкую тень.

Transition:

150–220ms

Active:

```text
translateY(0)
scale(0.98–0.99)
```

Анимация должна ощущаться точной и спокойной.

---

# 15. ССЫЛКИ

Использовать:

```text
→
```

или

```text
↗
```

там, где это действительно помогает.

На hover стрелка может смещаться на 2–4px.

Не анимировать весь link block.

---

# 16. STATUS UI

Использовать статусы по всему сайту.

Примеры:

```text
● В работе
✓ Завершено
○ Следующий этап
! Требует внимания
```

Цвета должны быть сдержанными.

Не использовать кислотные неоновые состояния.

Рекомендации:

success:
приглушённый зелёный

warning:
приглушённый янтарный

critical:
приглушённый красный

accent:
индиго

---

# 17. METRIC UI

Крупные числа использовать как визуальные якоря.

Например:

```text
12 900 ₽/м²
45 дней
3 года
37 пунктов
```

Структура:

```text
большое число
маленькое объяснение
```

НЕ помещать каждую цифру в разноцветный рекламный badge.

Числа должны ощущаться как продуктовые метрики.

---

# 18. СЕКЦИЯ ПРОБЛЕМ

Секция «Что обычно идёт не так» должна визуально напоминать product diagnostic interface.

Каждая карточка:

* номер;
* страх/проблема;
* короткое объяснение;
* «Что делаем мы».

Пример:

```text
01

Смета вырастает

Проблема
...

Решение
...
```

На hover:

* слегка изменяется border;
* появляется акцент;
* может раскрываться решение.

На mobile:

обычная вертикальная структура без hover-зависимости.

Страхи не преувеличивать.

Тон остаётся спокойным.

---

# 19. PROBLEM PROTOCOL

Это одна из главных секций сайта.

Последовательность:

```text
ПРОБЛЕМА
↓
ФИКСИРУЕМ
↓
ОБЪЯСНЯЕМ
↓
ПРЕДЛАГАЕМ ВАРИАНТЫ
↓
СОГЛАСОВЫВАЕМ
↓
ВЫПОЛНЯЕМ
```

Сделать визуально похожим на workflow.

Desktop:

горизонтальная схема.

Mobile:

вертикальный timeline.

Каждый шаг может содержать:

* номер;
* статус;
* название;
* короткое описание.

При scroll активный этап может подсвечиваться.

Анимации:

* opacity;
* translateY;
* progress line.

Не использовать чрезмерное движение.

# 20. TIMELINE ПРОЦЕССА

Процесс ремонта должен визуально напоминать workflow внутри продукта.

Этапы:

```text
01 Замер
02 Проект
03 Смета
04 Договор
05 Закупка
06 Ремонт
07 Контроль
08 Приёмка
09 Клининг
10 Ключи
```

Использовать:

* тонкие линии;
* маленькие маркеры;
* аккуратные active states.

НЕ использовать огромные иконки.

Сам процесс — визуальный элемент.

---

# 21. КАЛЬКУЛЯТОР / QUIZ

Калькулятор — главный conversion component сайта.

Он должен ощущаться как premium product UI.

Использовать:

* progress indicator;
* один вопрос за раз;
* понятные selected states;
* удобный ввод;
* большие tap targets;
* минимальное количество отвлекающих элементов.

Desktop:

калькулятор в большой центральной карточке.

Mobile:

один вопрос на один экран.

Пример:

```text
01 / 05
```

Выбранный вариант получает:

* акцентную границу;
* лёгкий фон;
* небольшой check icon.

НЕ использовать:

* мультяшные иллюстрации;
* игровые элементы;
* чрезмерное количество иконок.

---

# 22. РЕЗУЛЬТАТ КАЛЬКУЛЯТОРА

Результат — ключевой conversion moment.

Крупно:

```text
1,05–1,25 млн ₽
```

Ниже:

```text
64 м²
Новостройка
Комфорт
```

Далее:

```text
Получить подробную смету
```

Result card должна визуально ощущаться важнее предыдущих шагов.

---

# 23. РАЗБИВКА СТОИМОСТИ

Price breakdown должен выглядеть как финансовый/product UI.

Использовать:

```text
название
стоимость
разделитель
```

Пример:

```text
Работы                    612 000 ₽
Материалы                 428 000 ₽
Доставка                   46 000 ₽
Комплектация               74 000 ₽
───────────────────────────────────
ИТОГО                    1 160 000 ₽
```

Не добавлять график просто ради красоты.

График использовать только если он реально помогает понять бюджет.

---

# 24. СЕКЦИЯ МАТЕРИАЛОВ

Визуально — сравнение вариантов.

Три карточки:

```text
ПОКУПАЮ САМ

ЗАКУПАЕТЕ ВЫ

КОМПЛЕКТАЦИЯ
```

Карточки должны отвечать на вопрос:

**«Как я контролирую деньги и закупку?»**

НЕ использовать случайные stock-фото строительных материалов.

Предпочтительнее:

* UI-схемы;
* списки;
* статусы;
* стоимость;
* доставка;
* количество.

---

# 25. DESIGN PIPELINE

Процесс:

```text
3D
→
РАБОЧИЙ ЧЕРТЁЖ
→
СМЕТА
→
РЕАЛИЗАЦИЯ
```

Секция должна ощущаться editorial/product-like.

Хороший вариант:

один реальный объект проходит через четыре стадии.

Не использовать чрезмерный 3D UI.

Использовать реальные изображения проекта.

# 26. CASE STUDIES

Кейсы должны выглядеть как product case studies, а не Pinterest-галерея.

Структура:

```text
Название проекта
↓
Площадь
↓
Бюджет
↓
Срок
↓
Задача
↓
Проблема
↓
Решение
↓
Результат
```

Layout:

большое фото

*

компактная информационная панель.

Например:

```text
64 м²
82 дня
1 160 000 ₽
```

Информационная панель должна ощущаться как interface card.

НЕ накладывать огромные тексты на фотографии без необходимости.

---

# 27. ФОТОГРАФИЯ

Фотографии должны ощущаться:

* настоящими;
* архитектурными;
* премиальными;
* спокойными;
* естественно освещёнными;
* документальными.

Предпочитать:

* реальные квартиры;
* процесс ремонта;
* строительные детали;
* before/after;
* материалы;
* готовые интерьеры.

Избегать:

* типовых stock-фото строителей;
* рукопожатий;
* улыбающихся прорабов в касках;
* чрезмерно обработанных HDR-интерьеров;
* постановочных рекламных фотографий.

Фотография должна повышать доверие.

---

# 28. BEFORE / AFTER

Before / After должен быть минималистичным.

Можно использовать:

* drag slider;
* toggle.

Не делать из этого визуальный аттракцион.

Главное доказательство — сам результат.

---

# 29. CHECKLIST ПРИЁМКИ

Чек-лист из 37 пунктов должен ощущаться как настоящий QA-системный инструмент.

Визуально:

```text
37
пунктов проверки

✓ стены
✓ плитка
✓ электрика
✓ двери
✓ сантехника
```

Использовать компактные строки и маленькие status indicators.

# 37. ФИЛОСОФИЯ АНИМАЦИЙ

Motion должен объяснять:

* иерархию;
* прогресс;
* состояние;
* взаимодействие;
* переход между этапами.

Motion НЕ должен существовать только ради демонстрации технического мастерства.

Предпочитать:

* opacity;
* transform;
* scale;
* width;
* height.

Избегать тяжёлых:

* blur-анимаций;
* сложных box-shadow animations;
* filter animations;
* постоянных фоновых анимаций;
* тяжёлого parallax.

---

# 38. SCROLL АНИМАЦИИ

Использовать:

* IntersectionObserver;
* либо лёгкие animation utilities.

Предпочтительно:

* fade-up;
* fade-in;
* progress reveal.

Duration:

400–700ms

Easing:

```css
cubic-bezier(0.22, 1, 0.36, 1)
```

Stagger:

50–100ms

Не анимировать каждый текстовый элемент.

Максимум:

1–2 осмысленных motion-события на секцию.

---

# 39. HOVER STATES

Hover должен быть минимальным.

Карточки:

слегка меняют border.

```text
translateY(-1px)
```

Ссылки:

стрелка немного двигается.

Кнопки:

небольшое изменение цвета / позиции.

Dashboard:

элемент получает лёгкую подсветку.

НЕ использовать:

* сильное увеличение;
* glowing borders;
* неон;
* чрезмерный scale;
* карточки, «летящие» на пользователя.
